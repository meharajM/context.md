# `src/features/meetings` Architecture

Meeting mode is an unreleased, local-only user flow. `MeetingScreen` uses store actions for capture, recovery, retention, action review, and saving content to the note library; it does not call native modules or persistence services directly. Start is enabled only when platform transcription is ready: Android Whisper or selected iOS Gemma 3n E2B. `startMeeting` also returns a meeting-specific error when setup or permissions fail so the screen can show retryable inline feedback without relying on the shared status message. Stop automatically starts summary and action generation after transcript persistence; Meeting summary inference has no separate memory/thermal preflight. If on-device inference is unavailable or fails, the store selects up to three deduplicated transcript sentences as a clearly labeled `summarySource: 'transcript'` fallback; UI, sharing, and saved notes preserve that label. One missing summary retries on foreground; enabling or downloading the writing helper also retries it. If the app closes during summary inference, the transcript remains durable and the summary resumes automatically on the next foreground. A failed automatic retry does not loop on every launch. Action suggestions are persisted even when the writing helper is unavailable or inference fails, and retries preserve user review state. Slow bounded inference calls retry with smaller transcript chunks while preserving all source text; invalid/raw-fallback model output now takes the same smaller-chunk retry path as context-limit and timeout errors. The retry has two split depths per part and can still fail or time out on a device that cannot run the selected model, while transcript and actions remain available. A 63-minute Redmi transcript previously returned a raw LiteRT fallback; the new retry is covered by a source-preserving Jest test, but the long physical summary has not been retested after this change. The core store pauses pending note synthesis while a meeting is active and restores the model/resource gate after finalization. Already-running synthesis finishes before a meeting chunk is transcribed; capture continues during that wait, and a timeout leaves the full WAV available for retry. Startup refreshes readiness after the platform transcription model is available. Suggested actions use conservative local rules, retain a recognized person or team actor, and require explicit review; they do not schedule reminders. Retrying a recovered recording applies the same queue pause and prevents a second capture until it finishes. Share actions are passed from AppShell and use the OS share sheet. `meetingRepository` stores revisioned session JSON under the app Documents directory. Android/iOS widgets only open this screen; Start remains an explicit in-app action. Meeting timers and transcript timestamps switch to HH:MM:SS at one hour.

Each meeting stores timestamped transcript segments, optional summary and suggested actions, recording state, saved-note identity, and retained audio metadata. The full WAV stays in app-owned retained storage until both recording and transcript persistence finish and the configured interval elapses. Transcription failure preserves audio. Library JSON backup excludes meeting sessions and audio, but includes a meeting note after the user saves it to the library.

Meeting action extraction uses local commitment and action-label cues, independently from reminder-date planning; weekday-only deadlines may remain in a suggested action without creating a scheduled reminder. A standalone spoken “Action item.” or “Next step.” marker applies to the next sentence. Negated/completed tasks are filtered, and each suggestion remains user-confirmed or dismissed.

Signed Android 1.0.8/code 9 `.deviceTest` QA (Redmi 3S/API 30, no Metro): background room-mic capture and the persistent recording notification worked; a timestamped transcript chunk appeared before Stop; when the writing helper was absent, Stop generated labeled transcript highlights and the meeting saved to one Inbox note. Whisper misrecognized the synthetic action phrase, so the physical run did not verify that action suggestion; the standalone-marker regression is covered by the store test. The older 63-minute capture still lacks a verified on-device summary.

Latest signed release-mode physical QA used the isolated `.deviceTest` app with the optional writing model absent. A 1:34 microphone capture continued after Home, Android kept the mic privacy indicator and “Recording meeting” notification, and the app showed a timestamped transcript chunk before Stop. Stop automatically persisted transcript highlights and three reviewable action suggestions. Saving created one stable Inbox note. Android chooser previews were checked for summary-only, transcript-only, action-only, and all sections; no destination was selected. Speech recognition misheard “Meeting test” as “Meet and Test,” yielding a low-confidence extra suggestion. The 63-minute model-summary failure was a raw fallback response; smaller-chunk retry was added after that run and is covered by Jest, but has not yet been verified with the optional model on-device.

Sharing offers summary only, timestamped transcript only, suggested action items only, or all available sections through the native share sheet. Unavailable sections are disabled, and action review states are included. “Share everything with an assistant” adds an analysis prompt requesting plain text capped at 250 words, with fixed headings for key findings, decisions, risks, next steps, and open questions; it asks the assistant to omit empty headings and avoid repeating the notes. Saving still creates or updates one stable Inbox note with all available content, so later summary changes refresh the same note without duplicates; audio is never copied into the note.
